# Zeist Chess on the web

Each engine has its own page under Zeist's Chess: `zeist.gg/chess/vs/<id>/`, such as `/chess/vs/maia/`. Zeist's
Chess lists the engines in its opponent picker (from `/chess/vs/engines.json`) and links to these pages; Back goes to
`/chess`. The pages are drawn as Zeist's own Chess screens: a start screen with the engine, its level (1 to 10) or, for
Maia, a rating, the side and the clock (none, 10+5 or 15+10), then the game. Games against these engines are not rated.

The engine is downloaded on the first game, checked file by file, kept in the browser and run there in a Web Worker,
offline from then on. Games are kept in the browser. Nothing runs on a server but a small Worker that hands out files.

## What is here

| Path | What |
|---|---|
| `pages/vs.html` | An engine's page: the start screen, the game, How to play. Written once per engine by `scripts/assets.mjs`. |
| `public/js/vs.js` | The page's screens: choices kept for next time, the download on first play, the game, the result. |
| `public/js/board.js` | The board: theme, coordinates, pieces that glide, tap or drag, promotion. |
| `public/js/play.js` | A game against an engine: turns, clocks, take-backs, resign, the end. |
| `public/js/engine.js` | One engine at a time through `core/host.js`, at the level `core/levels.js` sets. |
| `public/js/shelf.js` | The catalog, downloads checked by sha256, packs kept in Cache Storage. |
| `public/js/log.js` | Every game in IndexedDB, with the iPhone app's field names. |
| `public/js/account.js` | Signed in with Zeist through `GET /api/me` on the same origin, else signed out. |
| `public/js/config.js` | Where packs are downloaded from (`PACKS`) and where Back goes (`HOME`); the site's copy is written from `ZC_PACKS` and `ZC_HOME`. |
| `public/z/` | Zeist's own stylesheets, copied so the pages look like Zeist's Chess. |
| `public/vs.css` | What those don't draw: this board, the rating slider, clocks beside the players. |
| `public/sw.js` | Offline: the pages and files, and downloaded packs (served only from what was checked). |
| `src/worker.js` | The Worker: packs under `<base>engines/` (until engines.zei.st sends CORS headers), and a redirect to `/chess` for anything unknown. |
| `scripts/assets.mjs` | Builds `site/`: the files laid out at the base path, a page per engine, `engines.json`, `_headers`, the shell and the pins. |
| `scripts/serve.mjs` | A plain Node server that answers as Cloudflare does: a file of `site/`, else the Worker's handler. |
| `test/run.mjs` | The headless test suite (Playwright, Chromium and WebKit). |

`public/core/`, `public/pieces/` and `site/` are generated by `scripts/assets.mjs` and not committed.

## Run it

From `web/`, with Node 24 and Python 3:

```sh
npm install
node scripts/assets.mjs          # builds site/ at /chess/vs/
node scripts/serve.mjs           # http://localhost:8790/chess/vs/stockfish-lite/
```

`serve.mjs` takes `--port`, `--engines ../engines/dist` to serve packs from disk, and `--packs-origin <url>` to act
as a site built with `ZC_PACKS`. Zeist's own pages (`/chess`, `/api/me`) are not there locally, so Back and sign-in
lead nowhere.

`npm run dev` runs Cloudflare's dev server (`cf dev`) on the same `site/`.

## Test it

```sh
node scripts/assets.mjs
PLAYWRIGHT_DIR=<playwright folder> node test/run.mjs [chromium] [webkit] [--engines ../engines/dist]
node test/units.mjs              # the clock and flag rules, no browser
```

`PLAYWRIGHT_DIR` is a folder where Playwright and its Chromium and WebKit are installed (Playwright is not a dependency
of this repo). The suite runs two local sites, one downloading packs from a stand-in packs server that sends CORS
headers and one from a stand-in that doesn't, and checks: `engines.json`; an unknown engine going to `/chess`; the start
screens of Stockfish Lite and Maia; a game at level 1 with no clock, with no request reaching the Worker; Back and
Continue; a reload with no network; a 10+5 game with its clocks, resigned from the menu; a broken engine; the fallback
to the Worker without CORS; a signed-in name; and that nothing asks for `/api/rated`. Screenshots go to `SHOTS`
(default `screenshots/`).

## Deploying

```sh
npm install
ZC_BASE=/chess/vs/ node scripts/assets.mjs     # add ZC_PACKS=https://engines.zei.st/ once it sends CORS headers
CLOUDFLARE_ACCOUNT_ID=<account> ZC_BASE=/chess/vs/ ZC_ROUTE='<domain>/chess/vs/*' ZC_ZONE=<domain> npx cf deploy --mode production
```

What the deploy creates or needs:

- **Worker** `zeist-chess`, from `cloudflare.config.ts`, with static assets from `site/` (`publicDir` in
  `vite.config.ts`). `workersDev` and preview URLs are off.
- **Static first.** `runWorkerFirst` is off: the pages, `engines.json`, scripts, styles, fonts and pieces are assets,
  served by Cloudflare without running the Worker, with the headers in `site/_headers` (each page's content security
  policy, `no-cache` on pages and the service worker, five minutes on `engines.json`, a month on fonts and pieces). The
  Worker runs only when no asset matches: `<base>engines/...` and unknown addresses.
- **Bindings:** `ENGINES`, the R2 bucket `zeist-chess-engines`, read only; `BASE` and `HOME` as text.
- **Route:** `ZC_ROUTE` on `ZC_ZONE`, such as `zeist.gg/chess/vs/*`, more specific than Zeist's own route.
- **Engine pages:** one per engine in the catalog, in `engines/order.json` order. Zeist and the names the app uses for
  its own folders are never pages. `<base><id>` gets its slash; anything else under the base goes to `/chess` (302).
- **Packs.** With `ZC_PACKS` set, the browser downloads packs from that origin directly (it must answer the site with
  CORS headers, below); a failed request there falls back to `<base>engines/` for the rest of the visit. Without it,
  packs come through the Worker. Either way the files are kept under `<base>engines/<id>/` in this origin's Cache
  Storage and the service worker serves them from there, so the engine's worker is a same-origin script.
- **CORS on engines.zei.st,** needed before `ZC_PACKS` is set: a CORS policy on the R2 bucket allowing `GET` and `HEAD`
  from the sites that serve these pages, for example:

  ```json
  [{ "AllowedOrigins": ["https://zeist.gg"], "AllowedMethods": ["GET", "HEAD"], "AllowedHeaders": [], "ExposeHeaders": ["Content-Length", "ETag"], "MaxAgeSeconds": 86400 }]
  ```

  Downloads send no credentials and no custom headers, so the browser makes no preflight request.
- **Sign-in:** `GET /api/me` on the same origin (Zeist's Worker answers it). Nothing else on Zeist's API is called.

No secrets are needed.

## How things work

- **Engines and their integrity.** Downloading reads the pack's manifest and checks it against the catalog's record
  (`manifest_sha256`), fetches every file into a staging cache, checks its size and sha256 against that manifest, and
  only then swaps it into Cache Storage (`zc-packs`), the manifest last, so a pack is never half there. The service
  worker answers pack requests only from there, only for files the kept manifest lists, and never from the network.
- **The pins.** Cache Storage belongs to the whole site, so nothing kept there is trusted on its own. `scripts/assets.mjs`
  writes into `shell.js` (`self.PINS`) the `manifest_sha256` of every pack version the catalog lists, kept in
  `engine-pins.json`, which only ever grows. Every time a pack file is served, the kept manifest must hash to a pinned
  value and the file must match that manifest. A file that fails is damage: the pack is removed and the page says so.
  A catalog change needs a web redeploy to be installable.
- **Engines that fail.** A worker that errors or does not answer is retried once (untimed games); after that the game
  says the engine stopped and offers Try again. The board never freezes.
- **Games** are kept in IndexedDB with the fields of the iPhone app's `GameRecord`. They are never rated and never
  sent anywhere: Zeist's archive takes only games against its own engine.
- **Clocks.** None, 10+5 or 15+10. The clocks start with White's first move, stop while the game is out of sight, and
  a fallen flag loses unless the other side cannot checkmate. Take-backs only without a clock.
- **Keyboard.** Left and right step through the moves, Home and End go to the start and the end, Escape lets go of a
  selected piece.
